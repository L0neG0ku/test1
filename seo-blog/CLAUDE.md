# CLAUDE.md: Kribble SEO package

You are helping the Kribble team deploy an SEO package for Kribble (https://www.kribblecare.com): a 33-post blog, homepage SEO fixes, and an outreach kit. Kribble is a pre-launch childcare discovery app, launching first in Gurugram. Work through the steps below in order. Explain what you are doing in plain language, show diffs before changing the website files, and ask before anything that publishes or deploys.

## Ground rules

1. **FACTS.md is the source of truth.** Never add a product claim, number, price, customer or feature that is not in FACTS.md. If the team gives you a new fact, add it to FACTS.md first, then update the posts.
2. **Never publish or deploy without an explicit yes** from the team in this session.
3. **Never post to Reddit, Hacker News, forums or social media**, and never send outreach emails. The `outreach/` folder is for the team to use by hand. You may help edit drafts.
4. **Keep `launch_date` fixed** in `site.json` once set. Posts are scheduled as days after it (`day:` in each post). Changing it reschedules everything.
5. **Do not edit `dist/`** by hand. It is regenerated by `python3 build.py` every time.
6. **Never run `python3 build.py --all` before a deploy.** `--all` includes scheduled posts and is for local preview only.

## What's in this folder

| Path | What it is |
|---|---|
| `content/posts/*.md` | 33 blog posts with SEO front matter |
| `build.py` | Static blog builder, Python standard library only |
| `site.json` | Site settings: URL, blog path, CTA, launch date, categories |
| `static/blog.css` | Blog styles; colour variables at the top |
| `static/og/*.png` | Social share images, one per post, plus default, home and logo |
| `FACTS.md` | Product facts, stated limits, claims to avoid, open items |
| `seo/homepage-head.html` | Paste-in `<head>` tags and JSON-LD for the homepage |
| `seo/homepage-fixes.md` | Prioritised homepage and site checklist |
| `seo/keyword-map.csv` | Target searches mapped to pages |
| `seo/content-calendar.csv` | Publishing order (days after launch) |
| `outreach/` | Threads to reply to, reply drafts, directories to submit to |
| `tools/make_og_images.py` | Regenerates share images (needs Playwright; optional) |

`python3 build.py` writes to `dist/`:

- `dist/blog/` (index, 6 category pages, one folder per published post, `rss.xml`, `blog.css`, `og/`)
- `dist/sitemap-blog.xml`
- `dist/llms.txt` and `dist/llms-full.txt`
- `dist/robots.suggested.txt` (merge into the site's robots.txt; do not overwrite blindly)

## First run: deploy the package

### Step 1. Ask the team four things (one message)

1. Where is the website's source? (a local folder path or a git repo to clone)
2. How is it deployed today? (Vercel, Netlify, Cloudflare Pages, GitHub Pages, a server, something else)
3. What is the launch date? (default: today; posts with `day: 0` publish on that date)
4. Are they happy to publish the 8 day-0 posts at launch, with the other 25 released over the following three weeks? (see `seo/content-calendar.csv`)

### Step 2. Check the environment

- `python3 --version` must be 3.8 or newer. Nothing else is needed for the build.
- Run `python3 build.py --all` once and open a few pages from `dist/blog/` to confirm it works. Then delete the effect by restoring `launch_date` to `null` in `site.json` if `--all` set it, and continue.

### Step 3. Inspect the website source

Find out:

- The framework or generator (plain HTML, Astro, Next.js, Hugo, Eleventy, Jekyll, other)
- Which folder is served as-is at the site root (for example `public/`, `static/`, or the repo root for plain HTML)
- Whether `robots.txt`, `sitemap.xml`, `favicon.ico` and `llms.txt` already exist
- Where the header navigation and footer are defined
- The site's colours and fonts (read its CSS)

### Step 4. Match the design

Edit the variables at the top of `static/blog.css` (`--bg`, `--surface`, `--line`, `--text`, `--muted`, `--accent`, `--accent-ink`, `--link`, `--font`) to match the main site exactly. If the site loads a web font, add the same font to `--font`. If the header links in `build.py` (`Blog`, `Gurgaon guides`, `For centres`, CTA) don't match the live site, update the `head()` function.

If the colours change, regenerate the share images (`python3 tools/make_og_images.py`, after `pip install playwright && python -m playwright install chromium`) and update the colours in that script first. If Playwright can't be installed, keep the shipped images.

### Step 5. Set the launch date and build

- Set `"launch_date": "YYYY-MM-DD"` in `site.json`.
- Run `python3 build.py`. Fix every warning it prints before going further (title and description lengths, internal links, keywords).
- Fill in `twitter_handle` in `site.json` if Kribble has one.

### Step 6. Put the output into the site

Copy, do not move:

- `dist/blog/` → `<served root>/blog/`
- `dist/sitemap-blog.xml` → `<served root>/sitemap-blog.xml`
- `dist/llms.txt` and `dist/llms-full.txt` → `<served root>/` (if an `llms.txt` exists, merge)
- `dist/robots.suggested.txt` → merge into `<served root>/robots.txt`, keeping any existing rules and adding the `Sitemap:` lines

Framework notes:

- **Plain HTML, Astro, Hugo, Eleventy, Jekyll, GitHub Pages, Cloudflare Pages, Netlify:** files under the static folder are served as-is and `/blog/slug/` resolves to `/blog/slug/index.html` automatically.
- **Vite on Vercel (Kribble's setup):** copy the output into `public/` so Vite copies it into the build. Vercel serves real files before applying rewrites, so `/blog/slug/` returns `public/blog/slug/index.html` even with an SPA catch-all rewrite. Confirm locally with `npm run build && npx vite preview`, then check a post URL with and without the trailing slash, and add `"trailingSlash": true` in `vercel.json` if the slashless URL does not redirect.
- **Next.js:** files in `public/` are served, but `/blog/slug/` does not automatically serve `index.html`. Either set `trailingSlash: true` and add a rewrite from `/blog/:path*/` to `/blog/:path*/index.html` in `next.config.js`, or on Vercel set `"cleanUrls": true` and `"trailingSlash": true` in `vercel.json`. Test both `/blog/` and one post URL locally before deploying.
- **Anything else:** make sure `/blog/` and `/blog/<slug>/` return the generated `index.html` with status 200, and that `/blog/<slug>` (no slash) redirects to the slashed version, because the canonical URLs end in `/`.

### Step 7. Apply the homepage fixes

Work through `seo/homepage-fixes.md` items 1 to 8 (the "must fix" list). For each: show the team the change as a diff, apply it after they agree, and tick the box in the file. Use `seo/homepage-head.html` for item 2, after filling its TODOs with the exact FAQ answers shown on the page. Point `og:image` at `/blog/og/home.png`. Item 1 (prerendering) is the most important and the most technical: propose the approach that fits the repo, test it locally, and explain it in plain words before applying. Item 7 changes visible copy: get explicit approval for the exact wording.

### Step 8. Check before deploying

Run the site locally (its usual dev or preview command, or `python3 -m http.server` from the served folder for plain HTML) and confirm:

- `/blog/`, two posts, one category page, `/blog/rss.xml`, `/sitemap-blog.xml`, `/llms.txt` and `/robots.txt` all load
- The homepage shows the Blog link
- Every JSON-LD block parses (extract each `<script type="application/ld+json">` and run it through `python3 -m json.tool`)
- No page links to `#` where it should link to a real page

### Step 9. Deploy

Use the site's existing deploy method (usually commit and push). Ask first. After it is live, check with `curl -sI` that the homepage, `/blog/`, a post, `/sitemap-blog.xml`, `/robots.txt` and `/llms.txt` return 200, and that the homepage HTML contains the new `<title>`.

### Step 10. Hand over the manual steps

Tell the team, in plain words, what only they can do:

1. Verify the domain in Google Search Console and Bing Webmaster Tools, submit `sitemap.xml` and `sitemap-blog.xml`, and request indexing for the homepage and the day-0 posts (`seo/homepage-fixes.md` items 16 and 17)
2. Validate structured data at https://search.google.com/test/rich-results
3. Work through `outreach/directories.csv` (priority 1 first) and `outreach/conversations.csv`, using `outreach/replies.md`
4. Fill in the open items at the bottom of `FACTS.md`

## Publishing the scheduled posts

25 posts go live on later dates. A post appears only when `build.py` runs on or after its date. Either:

- **Manual:** run `python3 build.py`, copy `dist/` as in step 6, and deploy, on each date in `seo/content-calendar.csv` (or simply twice a week), or
- **Automatic (recommended for Kribble on Vercel):** if the site is built in CI (GitHub Actions, Netlify, Vercel, Cloudflare), add this package to the site repo (for example under `seo-blog/`) and add a step that runs `python3 seo-blog/build.py` and copies its output before the site build, plus a daily scheduled rebuild (a cron-triggered workflow or a deploy hook). Set this up with the team if they want it.

## Adding or editing posts

Front matter fields (all on one line each):

```
---
title: Full headline shown on the page
seo_title: Under 60 characters, primary keyword near the start
description: 110 to 160 characters, includes the primary keyword
slug: url-slug
category: one of Choosing childcare, Gurgaon guides, Safety and trust, Working parents, Child development, For centres
keyword: primary search phrase
tags: comma, separated
related: slug-one, slug-two, slug-three
day: days after launch_date to publish
updated: YYYY-MM-DD (optional; set when you materially update a post)
---
```

Rules for every post:

- Facts only from FACTS.md; claims about other products must be current and fair
- At least three links to other posts, as `/blog/slug/`
- A `## Frequently asked questions` section with `### Question?` headings (it becomes FAQ structured data)
- Plain, specific language; say what the product cannot do where relevant
- Supported markdown: `##`/`###`/`####` headings, paragraphs, `-` and `1.` lists, tables, `>` quotes, fenced code, `**bold**`, `*italic*`, `` `code` ``, `[text](url)`

After adding a post: run `python3 tools/make_og_images.py` (if Playwright is available), then `python3 build.py`, fix warnings, deploy.

Refresh `daycare-in-gurgaon-guide` (it says 2026) and `preschool-fees-gurgaon` every January and set `updated:`. Review `creche-at-work-india` and `childcare-after-maternity-leave` whenever the labour codes or creche rules change.

## When product facts change

1. Edit FACTS.md.
2. `grep -rn "<old fact>" content/ seo/ outreach/ site.json` and fix every hit.
3. When an open item is answered (free for parents, launch date, verification checklist, centre pricing): add it to FACTS.md, then `grep -rn "TODO" content/ seo/` and replace every TODO it resolves, especially in `30-what-is-kribble.md`, `33-list-your-daycare-on-kribble.md` and `seo/homepage-head.html`.
4. Rebuild and deploy.
